# BOT 爆炸叙事挖掘与复用 SOP

- 案例：BSC `BOT`，`0xbcad9b1b85af1cd81437252bf50b87235c0b7777`
- 研究日期：2026-08-12
- 目的：复原“价格为什么动、系统何时能够看到、哪个 CA 可以被绑定”，而不是事后挑一条推文解释价格。
- 证据数据：`research/golden_dogs/cases/bot_2026_08.json`

第一波还明确排除了两类伪信号：`@CryptoBitxin` 与 `@munburanketto` 的 exact-CA 帖都发生在峰值后，只能标记为 `posthoc`；`@false2z` 虽然在峰值前，但已经晚于启动 165 秒，因此只能进入“正统 CA 选择/传播候选”，不能冒充源头。

## 2. “新头像”究竟是什么

当前头像是黑底、白色圆形机器人脸，只有两枚倾斜的黑色眼睛。关键不只是图像长相，而是它同时满足：

```text
身份资源爆点
├── 稳定账号：@bot / X user ID 2085838061347217408
├── 权威网络：X、xAI、Grok、Elon Musk、SpaceX 周边官方身份
├── 新资源：pbs.twimg.com 的头像 URL 发生变化
├── 可推断时间：图片 snowflake -> 09:46:59.958 PDT
├── 市场同步：下一毫秒级边界进入 09:47:00 爆拉 K 线
└── 后续确认：Banner 和官方帖依次补强产品身份
```

它是“官方产品身份被公开激活”的早期信号，不等于官方发行代币。系统必须立即调查所有同名 CA，并等待权威证据选出正统 CA。

历史事件发生时，旧系统只看帖子和市场异动，不能稳定捕获头像/Banner 变化。现在已有 Profile 全字段 Diff、资源时间解析和图片哈希，但尚未完成 24 小时常驻延迟验收；所以正确表述是“代码能够检测下一次变化”，不是“已经证明当时一定能在 1 秒内买到”。

```text

├── 身份确认：Banner +51s，证明不是单张图片噪声
├── Profile 语义：名称、Bio、网址、认证可共同确认产品身份
├── 权威关系网：@bot 与 Elon/Grok/SpaceX/SpaceXAI 当前互相关联
│   └── 只证明 2026-08-12 的当前状态，不能伪造历史 follow 时间
├── 产品入口：当前官网指向 x.ai/bot，可监控 Sitemap、标题、图片和文档 Diff
├── 传播预热：@sizzlezzzzzzzzz 在第二波前已给出主 CA
├── 正统 CA 选择：@false2z 在第一波峰前区分主合约与收费竞品
├── 钱包集群：多枚 provider 绑定钱包在首发后 60-255 秒买入
├── 官方确认：官方帖很晚，只适合作为后续确认或第三阶段信号
```

2026-08-12 的有限 Grok/X 补搜没有找到比头像资源更早、同时又能绑定主 CA 的公开官方证据。它只找到更晚的官方 thread 和事后 exact-CA 帖，因此不能为了讲故事把晚信号改写成源头。

## 4. 可复用调查步骤

### A. 建立候选集合

1. 从当日/当周异常涨幅、交易数和新币中找到候选，不用涨幅榜替代叙事判断。
2. 同名、同图、跨链合约全部进入竞争集合。
3. 为每个候选保存创建时间、第一笔交易、流动性、持有人和历史 K 线。

### B. 还原最早公共信号

1. 搜索 exact CA、名称、图片和官方域名。
2. 区分原始作者、权威确认者、传播者、钱包标签和事后晒单者。
3. 对 X 账号同时检查 timeline、头像、Banner、名称、Bio、网址、置顶帖和关注关系。
4. 对图片 URL 解码可验证的 provider timestamp，并另存内容 SHA-256。
5. 只使用来源真正发生时间；`first_seen_at` 单独记录系统延迟。

### C. 还原市场波次

1. 每次独立拉升建立 `wave_id`。
2. 在信号前后至少取 1 分钟 K 线与成交明细。
3. 计算信号相对启动的秒差，不能只写“差不多同时”。
4. 历史 FDV、OHLC 和倍数明确标记为近似值，不能冒充可执行报价。

### D. 绑定人物和钱包

1. X handle 必须绑定稳定 user ID。
2. 钱包标签必须保存 provider、交易哈希、区块和日志位置。
3. “账号说自己是某钱包”与“数据平台打标签”分开保存。
4. 至少跨多个 token 有完整盈亏分母，才可能从 `research_candidate` 升级。
5. `mstzera`、`Stigman__`、`rawrstarxdd`、`0xfanfanfan` 只有稳定 X 身份与 provider 钱包绑定，仍是研究候选。
6. `cryptomoon520` 虽然买得早，但七日 provider 数据显示 273 次买入、582 笔交易、套利标签和 39.7% provider 胜率；高频不等于选择能力，因此降级而非优先监控。
7. `@sizzlezzzzzzzzz`、`@false2z`、`@9999btcname` 也只进入传播候选；必须继续补跨币完整分母才能升级。

### E. 做因果判定

```text
候选信号
├── 发生在上涨之前？
├── 来源是否有权定义叙事？
├── 是否明确指向 exact CA？
├── 是否存在更早的竞争解释？
├── 是否只是行情起来后的传播/复盘？
└── 缺任何关键证据 -> 保持 WAIT
```

## 5. 监控实现节奏

```text
高优先级权威账号
├── Profile 轻量字段：目标 1-2 秒轮询
├── 头像/Banner 内容：仅 URL 变化时下载校验
├── Timeline：独立轮询，不阻塞 Profile
└── Following：对关系网每个节点做低频完整快照；不能只拉第一页
    ├── @bot 是否新增关注权威账号
    └── Elon/X/xAI/Grok/SpaceX 是否新增关注 @bot 或其他网络节点

事件出现
├── 立即冻结原始响应、URL、哈希和时间
├── 查询同名币与 exact CA 竞争集合
├── 查询 DeBot、链上和已登记钱包
├── 叙事门禁判定
└── 若最终决定买入，再读取实时 MC、流动性和可执行报价
```

刷新快不等于请求失控。10 个出口用于轮转和故障切换；单账号同一时刻只允许一个未完成请求，并需要退避、抖动和延迟指标。
