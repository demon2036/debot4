# DeBot4 爆炸叙事监控实施清单

- 更新时间：2026-08-12
- 代码目录：本地 `/home/john/debot4`，远程 `/opt/debot4`
- 当前运行约束：只开发、回放和冒烟验证；采集常驻服务、Grok 事件触发和自动交易保持停止。
- 核心目标：尽可能在价格爆拉前捕捉叙事状态变化，并把证据、exact CA 与决策时实时 MC 严格分开。

## 1. 一级能力边界

九类爆点必须与 `x/` 并列，不能继续散落在一个叙事大模块里：

```text
src/debot4/v6/
├── x/                         # X 帖子、转发、关系和 Profile 状态
├── identity_change/           # 身份变化
├── ownership_confirmation/    # 原作者/IP 持有人确权
├── authority_wallet/          # 权威钱包动作
├── product_leak/              # 产品、代码和文档提前泄露
├── real_world_event/          # 现实世界源事件
├── ecosystem_authority/       # 生态权威介入
├── distribution_access/       # 分发入口打开
├── risk_resolution/           # 风险解除
├── canonical_ca/              # 正统 CA 胜出
└── explosion/                 # 共享事件契约、状态库和调度；不判断买卖
```

每个一级目录只负责自己的证据采集和状态转换；所有模块输出统一的 `ExplosionEvent`，再交给现有叙事调查、CA 门禁和交易执行。

## 2. 统一事件契约

每个爆点至少保存：

```text
ExplosionEvent
├── event_id                   # 内容确定性 ID，避免重复报警
├── category / subtype         # 九类之一及具体事件类型
├── occurred_at                # 来源真正发生时间
├── first_seen_at              # DeBot4 首次看到时间
├── subject                    # 人、产品、Meme、钱包或 CA
├── actor_id / actor_role      # 稳定身份与权威角色
├── source_url                 # 可复核原始来源
├── evidence_hash              # 原始响应或内容摘要
├── previous / current         # Diff 前后状态
├── chain / token_address      # 如有 exact CA 才填写
├── confidence                 # verified/corroborated/reported/unknown
└── buy_eligible=false         # 爆点本身永远不直接等于买入
```

时间必须满足：`occurred_at <= first_seen_at <= decision_at`。最终决定买入时重新读取 MC、流动性、滑点和可执行报价，禁止使用采集时旧 MC。

## 3. 十个并列监控面

### X. X 监控

- 新帖、回复、引用、转发、删除和置顶变化。
- exact CA、产品名、人物名、图片和外链提取。
- 关键人物关系网：马斯克、CZ、链官方、创始人、员工、原作者和高影响 KOL。
- FxTwitter 只作为数据源；轮询器负责发现变化，不能假设 FxTwitter 会主动推送。

### 1. 身份变化 `identity_change/`

- Profile Diff：头像、Banner、名称、Bio、网址、位置、认证和组织关联。
- 图片保存内容哈希和感知哈希，URL 变化与图片内容变化分别报警。
- 置顶帖变化独立成事件。
- 关键账号新增关注/取消关注；必须拿到可验证的关系快照才产出事件。
- BOT 回归时间线：
  - `09:46:59.958`：`@bot` 新头像。
  - `09:47:00`：BOT 开始爆拉。
  - 约 `09:47:51`：Banner 更新。
  - `10:09:05`：官方 Grok Bot 推文，已晚于峰值约 22 分钟。
- 验收：以历史快照回放时，头像事件先于第一根爆拉 K 线，Banner 形成第二个独立事件。

### 2. 原作者/IP 持有人确权 `ownership_confirmation/`

- 原作者主动认领 Meme 或从否认变为认领。
- 原作者发布、回复、引用或置顶 exact CA。
- 原作者加入社区必须有公开、可复核证据，群内传言不算。
- 原作者接收创作者费用、代币或控制权，与权威钱包模块交叉确认。
- 官网、个人主页或官方资料新增 Meme/CA 链接。
- 验收：没有稳定身份和 exact CA 时只触发调查，不得给出官方绑定。

### 3. 权威钱包动作 `authority_wallet/`

- 已登记创始人、官方、员工、原作者和生态钱包第一次买入或收币。
- 创作者费用接收、首次领取、归属地址改变。
- PairCreated、加减 LP、迁移、跨链、回购和销毁的首次执行。
- 同一地址的授权、转账和 Swap 必须按交易语义区分，不能把收币误判为买入。
- 验收：事件包含链、区块、交易哈希、日志索引、钱包角色和 exact CA。

### 4. 产品与代码提前泄露 `product_leak/`

- 官网新路径、Sitemap、页面标题、图片、视频、JS bundle 和公开 API Diff；受 WAF 阻断的官方网页经审阅的只读镜像抓取，并保留官方证据 URL。
- 官方 GitHub 仓库 commit、release、文档和配置新增名称或 exact CA。
- App Store、扩展商店、模型页、开发者文档或公开 Demo 上线。
- 直播/视频只在取得可定位时间戳和原始来源后产出已验证事件。
- 验收：保存 URL、内容哈希、首次看到时间和前后 Diff；截图传言只能标记 reported。

### 5. 现实世界源事件 `real_world_event/`

- 名人给宠物、产品、机器人或角色命名。
- 新吉祥物、新角色、新口头禅和突发公共话题。
- 动物园、比赛、发布会、纪念日和预定活动。
- 主流媒体突然集中传播特定名称或形象。
- 验收：这类事件只生成叙事候选；没有官方绑定时不得选择同名 CA。

### 6. 生态权威介入 `ecosystem_authority/`

- 链官方、基金会、Launchpad、交易平台和核心员工的公开互动。
- 权威人员可验证的买入、加群或持续参与。
- 官方产品、演示、活动或文档直接使用 Meme。
- 验收：区分 source、authority、amplifier 和 posthoc；普通转发不能冒充官方确权。

### 7. 分发入口打开 `distribution_access/`

- 交易所、Alpha、钱包搜索、Launchpad 和行情平台首次收录。
- 开放充值、现货/永续交易、交易活动、积分任务或收益池。
- 新市场、新交易对和显著流动性加入。
- 验收：区分公告时间、接口实际可用时间和交易开放时间；晚到公告只能作为第二波信号。

### 8. 风险解除 `risk_resolution/`

- 原作者从否认、沉默或争议状态变为明确认领。
- 版权、资金、开发者、迁移和社区控制权争议得到可验证解决。
- LP 恢复、资金退回、迁移完成或关键漏洞修复。
- 状态机必须保留否认历史，不能只保存最新正面状态。
- 验收：至少一个原始解决证据；LP 锁定、放弃权限等常规动作本身不构成叙事爆点。

### 9. 正统 CA 胜出 `canonical_ca/`

- 为同名、同图和跨链候选建立竞争集合。
- 依据官方帖/官网绑定、创建时间、权威钱包、流动性和持有人迁移判断领先者。
- 原作者明确“没有官方代币”时，所有候选保持未绑定。
- 资金与持有人从竞争 CA 迁移时形成独立的 leader-change 事件。
- 验收：输出候选证据矩阵和唯一 leader；证据不足必须 `UNRESOLVED`，不得猜测。

## 4. 数据流与交易隔离

```text
十个监控面
├── 保存原始证据和前后快照
├── 生成 ExplosionEvent
└── 进入叙事调查队列
    ├── 还原源头和时间关系
    ├── 建立竞争 CA 集合
    ├── exact CA 门禁
    │   ├── 未绑定 -> WAIT
    │   └── 已绑定 -> 决策时实时重查
    └── 交易执行
        ├── 记录是否真正提交/成交
        ├── buy MC、滑点和失败原因
        └── 跟踪买入后 1h 最高 MC 与净收益
```

爆点模块不得调用下单器，也不得把“发现事件”写成“已经买入”。

## 6. 凭证与部署规则

- DeBot Cookie 只能放在仓库外的私有凭证目录，权限必须为 `0600`。
- 仓库忽略 `credentials/`、`debot_cookies.json`、`*.cred` 和本地运行状态。
- Cookie 内容不得进入 Git、日志、Markdown、测试夹具或命令输出。
- 本地和远程代码通过 Git 同步；凭证通过独立安全复制同步。
- 未收到明确恢复指令前，远程 DeBot4 常驻采集、Grok 事件调用和交易保持停止。
